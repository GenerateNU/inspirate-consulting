# Repository mocks

This folder contains test doubles for the repository interfaces in the data
layer. A mock has the same methods as the real repository, but it returns values
configured by a test instead of contacting PostgreSQL.

`greetingMock.go` is generated by Mockery. Prefer regenerating it when the
interface changes rather than editing the generated file by hand.

## Using a mock

Create the mock with a test's `*testing.T`, configure an expectation, and pass
it to the handler constructor. The test can then check the handler's result and
error behavior without Docker, Supabase, or a real database. See the
[handler guide](../../handlers/README.md).

## Testing & Creating Mocks with Mockery

When writing unit tests for handlers, you do not need a running Supabase/PostgreSQL instance. Instead, generate mock repositories using **[Mockery](https://vektra.github.io/mockery/)**.

### Installing Mockery

Install the pinned Mockery v2 release using the project's Go toolchain:

```bash
go install github.com/vektra/mockery/v2@v2.53.7
```

Ensure `$(go env GOPATH)/bin` (or `GOBIN`, if configured) precedes `/usr/bin`
in `PATH`. Older system binaries can fail with `package "context" without types`
on newer Go versions. The commands below use `go run` to avoid that ambiguity.

### Generating Repository Mocks

Whenever you add or update an interface in `internal/data/data.go`, regenerate the mock from the `backend/` directory:

```bash
# Generate a specific repository mock
cd backend
go run github.com/vektra/mockery/v2@v2.53.7 --name=GreetingRepository --dir=internal/data --output=internal/data/repo-mocks --outpkg=mocks --filename=greetingMock.go

# Media access: use the interface name, not the implementation directory name.
go run github.com/vektra/mockery/v2@v2.53.7 --name=MediaAccessRepository --dir=internal/data --output=internal/data/repo-mocks --outpkg=mocks --filename=mediaAccessMock.go
```

The generated mocks will be placed in `internal/data/repo-mocks/` and can be injected directly into your handler tests without requiring Docker or Supabase.
